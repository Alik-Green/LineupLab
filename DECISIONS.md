# Decisions and evidence

1. **Missing fixtures:** the checkout and remote main contain no ZIP or sample JSONs. Do not fabricate “real pack” results. Implement the supplied schema, generate explicitly synthetic security/round-trip fixtures, and leave real-pack counts, visual comparisons and lens-anchor verification pending.
2. **Game safety:** no game process handles, memory reads, hooks or injection. Window-title enumeration is used only to choose a monitor. Capture is ordinary pixels; the overlay requests Windows capture exclusion. Valorant must use Borderless/Windowed mode.
3. **Portable core:** Tauri shells are excluded from the core Cargo workspace so `cargo test -p lineuplab-core` does not require WebView/Android toolchains. They reference the same core by path and retain independent lockfiles.
4. **Images:** original imported bytes are immutable and SHA-256 addressed. Derivatives live separately. Unknown JSON fields and original attribute string forms survive export; new fields are confined to `x_lineuplab`.
5. **Lens coordinates:** use top-left inset placement provisionally, normalized to image width (size) and image width/height (position). The requested legacy fixture is unavailable, so this is not represented as verified reverse engineering.
6. **Conflict resolution:** compare UTC timestamp, then revision, then deviceId. Deletes are tombstones. Probable duplicates are warnings, not automatic deduplication.
7. **Environment:** only the session's allowed package hosts are used. Rust is installed outside the repository; CI uses official rustup and normal registries. No Riot art is committed.
8. **Capture adapter location:** the `CaptureProvider` trait and deterministic mock live in core; the small xcap/Win32 implementation lives in the Windows desktop shell. This keeps even cross-target Cargo resolution portable.
9. **Current roster defaults:** the 30-agent roster available on 2026-11-06 includes Miks and Hush. Defaults are keyed by display name and resolved against the live UUID catalog; a wildcard handles future agents. New-agent lineupability choices are conservative and user-editable, not claims about optimal lineups. Roster cross-check: https://dotesports.com/valorant/news/all-known-agents-in-valorant (updated 2026-11-01).
10. **Missing referenced media vs absent fields:** a present path that cannot be resolved leaves the slot empty/incomplete. Fallback to projectile/step images is only for absent/null primary fields, and never invents stand2/aim2 from unrelated steps.
11. **Round-trip equality:** export renames media to `asset_<8hex>.<ext>`, so strict JSON tests compare media references by content hash. Projectile-only circle canonicalization is an intentional legacy-visible change required by the merge rule; it is tested separately from strict canonical-JSON equality.
12. **WebP compatibility:** default legacy export includes both a JPEG view for the old app and the original WebP. `x_lineuplab.originalMedia` lets LineupLab recover original bytes, so default export/re-import remains lossless.
13. **Undo overwritten imports:** new records are tombstoned; overwritten records are restored from a backup with a fresh revision/timestamp. Records claimed by a later import are not silently reverted.
14. **Abyss coordinates:** identity transform verified against the valorant-api `displayIcon` orientation for “Mid Bend -> B Site” `(0.6919,0.7016) -> (0.3441,0.8831)`. The HUD minimap is rotated relative to `displayIcon`; do not apply HUD orientation to `displayIcon`. See `docs/COORDINATE_CHECK.md`.
15. **UI adapter boundary:** shared UI talks to `LibraryAdapter`; `TauriAdapter` invokes Rust commands, `BrowserAdapter` provides a localStorage/synthetic-image demo for Linux dev and tests. Mobile uses the same browse UI with mutation controls hidden.
16. **Lens rendering:** SVG viewBox uses natural image pixels so circles stay circular; lens is a square sized by image width, clamped inside the image, and crops the original full-resolution source around the circle. Dragging the inset updates `zoomX/zoomY` only.
17. **Hotkey defaults:** the condensed task did not retain the exact original key list, so a complete Alt-based default set covering capture, crosshair circle, slot navigation, save/discard/undo, overlay Create/View and flipping was chosen and documented in `docs/HOTKEYS.md`; every binding is rebindable with conflict detection.
18. **Capture timing:** target <150 ms is measured and surfaced (`exceededTarget`) rather than enforced by dropping captures; Linux tests use the mock provider and verify downscale/encode/thumbnail behavior.
19. **Desktop DTO boundary:** Tauri commands translate core `mapId/agentId/video` to shared-UI `mapUuid/agentUuid/videoClip`, preserve `extensions`/unknown fields across saves, and store aim pins under `extensions.aimPins` (core pins remain stand/landing). Catalog art is served from the runtime cache via the asset protocol when available, otherwise the remote URL.
20. **Shell compile authority:** the sandbox vendor cache lacks Tauri/wry and crates.io egress is blocked, so the Tauri shell is source-complete but compiled/tested by Windows/Ubuntu CI rather than claimed as locally verified.
21. **Sync transport:** documented alternative to pinned HTTPS — LAN-only plain HTTP with six-digit pairing, constant-time compare, rate limiting and bearer tokens. Threat model and revocation in `docs/SYNC.md`; TLS deps are present for a future upgrade.
22. **Sync merge:** timestamp → revision → deviceId LWW, tombstones included; clients push newer local records + images then pull newer remote records. Conflicts are counted/reported rather than destructively merged.
23. **Android companion:** browse-only Tauri 2 shell sharing core + UI; sync is pull-only (no local edits pushed), min SDK 26. APK generation requires JDK/Android SDK/NDK and is delegated to CI; sandbox attempt failed on missing Java.
24. **CI fixes adopted:** Tauri async commands never hold SQLite references across await (sync runs on a dedicated current-thread runtime); catalog art paths are converted by the UI via `media_path` + `convertFileSrc`; Android CI installs SDK/NDK directly, aligns SDK env vars and sets `android.newDsl=false` for Tauri's Gradle plugin. Core CI runs without `--locked` due the offline vendor lockfile checksum gap.
25. **First GitHub release:** published `v0.1.0-preview.1` as a prerelease on the session branch (tag target `c6e5984d1daa6016c692236eb204ee8586b396bf`). Windows NSIS installer is unsigned; the CI Android APK was unsigned, so the release job zipaligned and signed it with an ephemeral self-signed preview certificate, verified the signature, and discarded the private key. This is explicitly not a production signing identity; future differently signed previews may require uninstall/re-pair. Release packaging runs inside GitHub Actions because the sandbox cannot reach the artifact-storage CDN; it verifies original artifact ZIP digests, package structure, uploaded SHA-256 checksums and APK signature before publishing. Windows/Android runtime behavior remains untested on real devices.
26. **UI redesign image layer:** catalog DTOs keep remote URLs and expose abilities/roles/map thumbnails; native commands return cache paths only through `catalog_image_url`, and the shared `ValImage`/`useCachedImage` layer applies `convertFileSrc`, remote fallback, one retry, skeleton and explicit error placeholders. Asset scope includes app-data/local-data/cache variants. First-run progress and Settings → Data self-test/audit make CSP/asset failures visible. Linux Playwright uses a dev-only mocked Tauri invoke/asset layer plus ignored fixture art; real Windows/Android rendering remains a manual verification item.
27. **Design system:** single token source in `ui/src/styles/app.css` (CSS variables + Tailwind v4 theme), self-hosted Inter/Barlow Condensed, shared `ui.tsx` component library with 40px desktop / 48px Android controls, chamfered red primary actions, side colors always labeled. Custom Windows title bar uses native window APIs; reference-site screenshots were unavailable under the host allowlist, so patterns were taken from knowledge and documented in `docs/DESIGN_NOTES.md` without copying assets.
28. **Browse defaults:** first map auto-selected so the minimap is never an empty checkerboard; agent/ability default to All; filters/split/sort/density/pinned agents persist in localStorage. Ability options are filtered by `core/data/lineup_abilities.json` (lineup-able only). Minimap markers use side-colored rings + ability icons, bounce pins, hover preview, two-way card selection, pan/zoom toolbar and labeled legend. Filters open in a popover to keep the minimap large.
29. **Create wizard (M4):** five steps (Setup → Capture → Pins → Details → Review) with a free-jump stepper, Back/Next, Save draft / Discard (confirm modal), 400 ms localStorage autosave + indicator and draft-recovery banner. Mode options resolve per agent+ability exactly like core `ModeConfig::modes`; switching mode merges its attributes and clears `extensions.attribute_forms` (core `switch_mode`). Capture auto-advances to the next empty visible slot and retake targets the last capture (core `DraftState`); Alt+X adds the crosshair circle to the last aim capture (core `add_focus_circle`). Validation mirrors core `validate_save` (required images + stand/landing pins + aim2⇒aim1) plus title/map/agent; hotkeys work on every step. Save returns to Browse; Save & Next keeps setup and restarts at Capture. Drafts stay device-local (no draft rows in the library). Editing an existing lineup opens at Capture. Fixed two latent bugs found by screenshot review: minimap click coordinates were clamped to (1,1) (missing /1000 normalization) and map URLs were double-resolved through the media layer.
